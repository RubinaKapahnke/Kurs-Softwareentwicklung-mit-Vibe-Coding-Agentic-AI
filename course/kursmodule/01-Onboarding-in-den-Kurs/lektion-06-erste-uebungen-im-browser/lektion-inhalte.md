# Lektion 06: Erste Übungen im eigenen Repository

## Ziel

Du machst deine ersten GitHub-Aktionen direkt im Browser und nutzt Markdown, um Inhalte lesbar zu strukturieren.

## Kapitel 1: Warum Markdown hier direkt wichtig ist

Auf GitHub werden besonders häufig Markdown-Dateien bearbeitet, zum Beispiel `README.md`, Notizen oder kleine Dokumentationen.

Markdown ist für den Kurs wichtig, weil du damit Inhalte schnell lesbar strukturieren kannst, ohne ein kompliziertes Textprogramm zu brauchen.

## Kapitel 2: Diese Markdown-Grundlagen solltest du kurz öffnen

Bevor du startest, schau in diese beiden Dateien:

1. [course/course-library/01-markdown/01-markdown-grundlagen.md](../../course-library/01-markdown/01-markdown-grundlagen.md)
2. [course/course-library/01-markdown/02-formatierung_md-files.md](../../course-library/01-markdown/02-formatierung_md-files.md)

Worauf du beim Lesen achten solltest:

- Wie Überschriften mit `#` funktionieren
- Wie Listen erstellt werden
- Wie Links geschrieben werden
- Wie du Text fett markierst

## Kapitel 3: Übung 1 - Neue Markdown-Datei anlegen

1. Add file -> Create new file
2. Dateiname: `uebung-01.md`
3. Trage einen Titel mit `#` ein
4. Ergänze einen kurzen Satz mit **fett** markiertem Wort
5. Ergänze eine kurze Liste mit 2 bis 3 Punkten
6. Füge einen einfachen Link ein, zum Beispiel zu deinem GitHub-Profil
7. Nutze den Reiter **Preview**, um die Darstellung zu prüfen
8. Commit changes mit passender Nachricht

### Mini-Beispiel für `uebung-01.md`

```md
# Meine erste Übung

Ich übe heute **Markdown** direkt auf GitHub.

- Punkt 1
- Punkt 2

[Mein GitHub-Profil](https://github.com/dein-username)
```

## Kapitel 4: Übung 2 - README bearbeiten

1. `README.md` öffnen
2. Stift-Icon klicken
3. Eine kurze Vorstellung ergänzen
4. Füge mindestens eine Überschrift, eine Liste und einen Link ein
5. Vorschau prüfen
6. Commit changes ausführen

## Kapitel 5: Commit-Historie im Browser prüfen

Nach deinen Änderungen solltest du direkt im Browser prüfen, ob deine Commits sichtbar sind.

So gehst du vor:

1. Öffne dein Repository auf GitHub
2. Klicke auf die Commit-Anzahl oder auf den Verlauf der Datei
3. Öffne den neuesten Commit
4. Prüfe, welche Zeilen hinzugefügt oder geändert wurden

So lernst du früh, dass GitHub nicht nur Dateien speichert, sondern auch die Veränderungshistorie sichtbar macht.

## Kapitel 6: Typischer Mini-Ablauf im Browser

1. Datei öffnen oder neu anlegen
2. Inhalt in Markdown schreiben
3. Preview prüfen
4. Commit-Nachricht eintragen
5. Commit ausführen
6. Historie kontrollieren

## Fallback

- Add file nicht sichtbar: In den Code-Tab wechseln.
- Commit-Button ausgegraut: Erst Inhalt einfügen.
- Vorschau sieht anders aus als erwartet: Noch einmal in die Markdown-Formatierungshilfe schauen.
- Link funktioniert nicht: Prüfen, ob `[]` und `()` richtig gesetzt sind.

## Erfolgskriterium

Du hast mindestens 2 Commits im Repository sichtbar und kannst einfache Markdown-Formatierungen direkt auf GitHub anwenden.
