# PRD: Grundlagen

Ein **PRD (Product Requirements Document)** ist ein Dokument, das beschreibt, was eine Software tun soll – bevor irgendein Code geschrieben wird.

---

## Wofuer brauche ich ein PRD?

Ein PRD beantwortet drei grundlegende Fragen:
- Was ist das Ziel der App?
- Wer nutzt sie und fuer was?
- Wann ist ein Feature fertig?

Ohne diese Klarheit arbeitet die KI ins Leere – oder erfindet Annahmen, die nicht zu deinem Projekt passen.

---

## PRD als KI-Kontext

Ein gutes PRD ist der wichtigste Kontext, den du einer KI geben kannst. Je klarer dein PRD, desto besser und zielgerichteter sind die KI-Antworten.

**Ohne PRD-Kontext:**
> "Erstelle eine Teilnehmerkarte."
> → KI erfindet Design, Datenstruktur und Inhalt nach eigenem Ermessen.

**Mit PRD-Kontext:**
> "Hier ist mein PRD: [PRD-Datei]. Erstelle eine Teilnehmerkarte."
> → KI nutzt Vision, User Stories und Definition of Done als Grundlage.

---

## Aufbau eines PRD

Ein einfaches PRD hat fuenf Abschnitte:

```markdown
## 1. Vision & Zielsetzung
[Ein Satz: Was ist das Ziel der App?]

## 2. Kernfunktionen (Features)
[Was soll die App koennen?]

## 3. Technische Leitplanken
[Welche Technologien/Tools werden eingesetzt?]

## 4. User Stories
- Als [Wer] moechte ich [Was], damit [Warum].

## 5. Definition of Done
- [Was muss stimmen, damit ein Feature als fertig gilt?]
```

Die wichtigsten Abschnitte fuer den Einstieg sind **1, 4 und 5** – sie geben der KI Vision, Nutzerkontext und Erfolgskriterien.
