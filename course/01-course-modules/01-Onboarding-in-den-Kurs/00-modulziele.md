# Kursmodul 01: Arbeitsumgebung, Dokumentation & Versionsverwaltung

## Kurzbeschreibung

Dieses Kursmodul befähigt Teilnehmende, eine arbeitsfähige Entwicklungsumgebung einzurichten, Projektdokumentation versionierbar zu schreiben und Änderungen nachvollziehbar über GitHub und Git zu teilen.

## Nach diesem Kursmodul können Teilnehmende

- VS Code für Kurs- und Projektarbeit nutzen
- Markdown-Dateien strukturiert schreiben
- GitHub und Git für Versionierung anwenden
- erste Produkt- oder Projektdokumentation versionierbar ablegen
- Dokumentation so schreiben, dass Menschen und KI sie als Kontext nutzen können

## Praxisartefakt

Ein eigenes Übungs-Repository mit versionierter README oder Projektbeschreibung sowie mindestens einem nachvollziehbaren Commit oder Pull Request.

## Rollenbezug

Relevant für Teilnehmende mit wenig oder viel Vorerfahrung, Product Owner, Projektmanager*innen, Fachbereich, Consultants, Technical Writer, Team Leads, Entwickler*innen, QA und Operations.

## Abschlussnachweis

Der Baustein gilt als abgeschlossen, wenn ein eigenes Repository eingerichtet, eine erste Dokumentationsdatei versioniert gespeichert und der Arbeitsablauf über GitHub oder Git nachvollziehbar genutzt wurde.

## Vereinbarter Ablauf Für Die Weiterentwicklung

Die Weiterentwicklung von Modul 01 erfolgt kompetenzorientiert und ohne feste Zeitplanung.

### Priorisierte Reihenfolge

1. Cloud-first: GitHub und Git sicher anwenden (Web-Editor und Codespaces je nach Aufgabe).
2. Markdown sicher anwenden, damit Dokumentation und Pull Requests sauber strukturiert sind.
3. Erst danach Wechsel zu lokalem Arbeiten mit VS Code und Terminal.

### Arbeitsmodus

- Viel Anleitung mit klaren Lektionfolgen und konkreten Befehlen.
- Anleitung ist als Sicherheitsnetz gedacht und kann bei Bedarf übersprungen werden.
- Fachbegriffe werden vor der ersten Nutzung erklärt oder direkt am Einsatzpunkt geklärt.
- Jede Lektion macht sichtbar, was jetzt getan wird, warum es jetzt dran ist und wofür es später gebraucht wird.
- Allgemeine Lerntipps und wiederverwendbare Hilfeinhalte werden in zentrale FAQ-, Glossar- und Bedienungshilfen-Dateien ausgelagert.
- Lernkontrolle erfolgt nur dort, wo sie didaktisch etwas prüft, als Verständnis-Check und ohne Dummy-Quizlogik.

### Git-Und Repo-Strategie

- Start im eigenen Übungs-Repository, danach Transfer ins Teilnehmer-Repository.
- Pull-Request-Workflow anfangs mit festen Vorgaben, bis die Git-Basics sicher sitzen.
- Cloud-Tools werden aufgabenbezogen gewählt: GitHub Web oder Codespaces.

### Abschluss Von Modul 01

- Mehrere kleine Pull Requests statt eines großen Abschluss-Pakets.
- Ergänzend ein Lern-Log mit den wichtigsten Erkenntnissen und offenen Punkten.
- Modul gilt als erfolgreich abgeschlossen, wenn die Aufgaben dokumentiert sind, ein eigenes Übungs-Repository mit erster Pull Request steht und die wichtigsten Git-Befehle sicher erklärt und angewendet werden können.

## Festgelegte Grobstruktur Für Lektion 04 Bis 16

### Didaktische Leitplanken

- Cloud-first bleibt bis zur sicheren Routine verbindlich.
- Lokales Arbeiten startet erst im letzten Modulteil.
- Jede Lektion folgt dem festen Format: Ziel, kurzer Kontext, frühe Aktion oder sichtbares Artefakt, Aufgaben, Fallback und optionaler Verständnis-Check.
- Lange Einstiegsblöcke ohne Aktion oder visuellen Reiz sind zu vermeiden.
- Aufgaben werden je Themenblock als Sammelaufgabe gebündelt.
- Hilfebefehle (Git, Terminal, Markdown) werden in jeder Lektion als eigener Abschnitt geführt.
- Dateinamen werden nach Lernpfad klar neu benannt: NN-thema-lernziel.md.

### Block A: Cloud-Grundlagen festigen

- L04: Repository-Struktur und Arbeitskontext im Kurs verstehen.
- L05: Git-Basics in der Cloud sicher anwenden.
- L06: Markdown für PRs, Issues und Lernnotizen nutzen.
- Sammelaufgabe A: thematisch gebündelte Umsetzung für L04 bis L06.

### Block B: Zusammenarbeit und PR-Qualität

- L07: Branching-Grundlagen in der Cloud.
- L08: Commit-Qualität und klare Commit-Nachrichten.
- L09: Pull Requests mit fester Vorlage.
- Sammelaufgabe B: drei getrennte Micro-Tasks.
- Review-Niveau: mittel (Kommentare aufnehmen und kleine Nachbesserungsrunde umsetzen).
- PR-Vorlage ist ab der zweiten PR verpflichtend.

### Block C: Übergang zu lokalem Arbeiten

- L10: VS Code und Git lokal installieren und prüfen.
- L11: Terminal in VS Code sicher nutzen.
- L12: Lokaler End-to-End-Workflow (clone, branch, commit, push, PR).
- Sammelaufgabe C: End-to-End plus kleine Konfliktlösung.

### Block D: Stabilisierung, Teamflow und Abschluss

- Alle drei Schwerpunkte sind gesetzt: Wiederholung/Stabilisierung, Teamflow/Review, Abschlussnachweise.
- L13 bis L15 verbinden Cloud- und Lokal-Workflow, typische Fehlerbilder und Review-Routinen.
- L16 bündelt den Abschlussnachweis und den Übergang in den Gesamtkurs.

### Abschlussnachweis-Format

- Abschluss über PR mit kombiniertem Nachweisformat:
	- Checkliste pro Übung mit Verweis auf Commit oder PR.
	- Tabelle mit Übung, Nachweislink, Status und kurzer Reflexion.
- Lern-Log ist ausführlich und enthält Reflexion pro Übung.
