# Lektion 04: Eigenes Übungs-Repository anlegen

## Ziel

Du erstellst dein erstes eigenes Repository auf GitHub und weißt danach, wofür es im Kurs gebraucht wird.

## Kapitel 1: Was ist dein eigenes Repository?

Ein Repository ist dein persönlicher Arbeitsbereich auf GitHub.

### Einfach erklärt

Ein Repository ist ein digitaler Projektordner im Internet. Dort liegen deine Dateien, deine Änderungen und der komplette Verlauf deiner Arbeit.

### Wofür ist ein Repository gedacht?

1. Du speicherst dort Code, Texte und andere Projektdateien.
2. Du kannst nachvollziehen, was du wann geändert hast.
3. Du kannst mit anderen zusammenarbeiten, ohne Dateien per E-Mail hin- und herzuschicken.
4. Du hast einen sicheren Ort für deinen aktuellen Stand und ältere Zwischenstände.
5. Im Kurs ist es der Ort, an dem du deine Übungen und Lösungen sammelst.

### Warum brauchst du dein eigenes Repository?

1. Das Kurs-Repository bleibt zentral.
2. Dein eigenes Repository ist dein privater Workspace.
3. Hier machst du Übungen und dokumentierst Fortschritt.
4. Die Trainerin kann Commits sehen und Feedback geben.
5. Du kannst später deine Arbeit sauber von den Kursinhalten trennen.

### Merksatz

- Kurs-Repository = Orientierung, Aufgaben und Lernmaterial.
- Eigenes Repository = deine Lösungen, Experimente und Commits.

## Kapitel 2: Vor dem Anlegen kurz prüfen

### Was du bereitlegen solltest

1. Deinen GitHub-Account.
2. Einen Repository-Namen, der noch frei ist.
3. Eine kurze Beschreibung, falls du sie eintragen möchtest.

### Woran du erkennst, dass du bereit bist

- Du bist bei GitHub eingeloggt.
- Du weißt, wie dein Repository heißen soll.
- Du hast verstanden, dass das Repository private Übungen enthalten soll.

## Kapitel 3: Einloggen und neues Repository öffnen

### Schritt 1: Einloggen

1. github.com öffnen.
2. Mit Account anmelden.
3. Falls du schon eingeloggt bist, prüfe oben rechts dein Profil-Icon.

### Schritt 2: Neues Repository

1. Profil-Icon klicken.
2. New repository auswählen.
3. Alternativ github.com/new.
4. Falls der Menüpunkt nicht sichtbar ist, öffne die direkte URL.
5. Wenn du die GitHub-Hilfe brauchst: [Quickstart für Repositories](https://docs.github.com/de/repositories/creating-and-managing-repositories/quickstart-for-repositories)

## Kapitel 4: Repository ausfüllen

### Die wichtigsten Felder

1. Repository name: `vibe-coding-uebungen` oder `mein-vibe-coding`
2. Description: optional, aber hilfreich für die Orientierung
3. Sichtbarkeit: `Private`
4. Initialize with README: aktivieren

### Warum diese Felder wichtig sind

- Der Name hilft dir, dein Repository später wiederzufinden.
- `Private` schützt deine Übungen vor öffentlichem Zugriff.
- Die README sorgt dafür, dass das Repository nicht leer wirkt.

### Hinweis

- Ohne README wirkt das Repository für Einsteigerinnen und Einsteiger oft leer und unklar.

### Copyright-Hinweis

- Kursinhalte nicht 1:1 öffentlich kopieren.
- Eigene Lösungen und eigenen Code kannst du veröffentlichen.

### Typische Stolperstellen

1. Name ist schon vergeben: hänge eine Zahl oder ein Kürzel an.
2. README ist nicht aktiv: Haken setzen, bevor du erstellst.
3. Sichtbarkeit falsch: Vor dem Erstellen noch einmal auf `Private` prüfen.

## Kapitel 5: README online mit GitHub.dev ausfüllen

GitHub.dev ist eine schlanke Online-Editor-Ansicht für GitHub-Repositories. Du kannst damit Dateien direkt im Browser bearbeiten, ohne dein Repository lokal zu öffnen.

### Wofür ist GitHub.dev gedacht?

1. Du willst schnell eine README oder eine andere Textdatei ändern.
2. Du möchtest direkt im Browser arbeiten.
3. Du brauchst nur eine einfache Bearbeitung und keinen kompletten lokalen Entwicklungsaufbau.

### So kommst du hin

1. Öffne dein Repository auf GitHub.
2. Drücke den Punkt `.` auf der Tastatur.
3. Oder rufe direkt `https://github.dev/<dein-benutzername>/<dein-repository>` auf.
4. Danach öffnet sich eine browserbasierte Editor-Ansicht.

### Was du dort mit der README machen kannst

1. Die `README.md` anklicken.
2. Den Text direkt im Editor ergänzen.
3. Speichern und den Commit für die Änderung ausführen.

### Kurz erklärt: Branch, Commit und Merge

- **Branch**: Ein eigener Arbeitszweig für Änderungen, damit der Hauptstand stabil bleibt.
- **Commit**: Ein gespeicherter Zwischenstand deiner Änderung mit Nachricht.
- **Merge**: Das Zusammenführen von Änderungen aus einem Branch in einen anderen.

Wenn du in GitHub.dev speicherst, wirst du oft gefragt, ob direkt in `main` oder in einem neuen Branch gearbeitet werden soll. Für den Kursstart ist beides ok, später arbeiten wir sauber mit Branches und Pull Requests.

### Wichtig

Auf Branch, Commit und Merge gehen wir in den nächsten Lektionen noch genauer ein.

### Hinweis

- GitHub.dev ist praktisch für Textdateien und schnelle Anpassungen.
- Für komplexere Arbeiten mit Terminal, Tests oder mehreren Dateien ist VS Code lokal besser geeignet.

## Kapitel 6: Repository erstellen und prüfen

1. Auf Create repository klicken.
2. Fertig.
3. Warte kurz, bis GitHub das Repository angelegt hat.

### Danach sichtbar

1. Repository-Name
2. README.md
3. Code-Button
4. Die Startseite deines neuen Repositories

### Mini-Kontrolle

1. Öffnet sich dein Repository ohne Fehlermeldung?
2. Siehst du eine README.md?
3. Steht oben der richtige Repository-Name?

## Fallback

- Das Plus fehlt oben rechts: Stelle sicher, dass du eingeloggt bist.
- Repository-Name ist vergeben: Füge eine Zahl hinzu.
- README fehlt nach dem Erstellen: Prüfe, ob der Haken vor dem Erstellen aktiv war.
- Du landest im falschen Bereich: Nutze github.com/new direkt.

## Erfolgskriterium

Dein Repository ist auf github.com angelegt, ist privat und enthält eine README.md.

## Was ist zu tun

1. Lege dein persönliches Übungs-Repository nach Anleitung an.
2. Prüfe Sichtbarkeit, Name und Basisinhalte (z. B. README).
3. Notiere den Repository-Link für deine Kurskommunikation.
