# GitHub: Grundlagen und Einstieg

Dieser Artikel erklärt GitHub allgemein und ohne konkreten Projektkontext.

## Was ist ein GitHub-Account?

Ein GitHub-Account ist dein Zugang zur Plattform [GitHub](https://github.com), auf der du Code speichern, teilen und gemeinsam bearbeiten kannst.

**In diesem Kurs brauchst du einen kostenlosen Account, um:**

- das Kursmaterial auf deinen Rechner zu holen (klonen)
- deine Lösungen zu speichern und zu teilen (Commits und Push)
- gemeinsam mit anderen zu arbeiten (Pull Requests)

👉 [Hier kannst du einen Account erstellen.](https://github.com/join)

<!-- onboarding:end github-account-lesson -->

## Was ist GitHub?

GitHub ist eine webbasierte Plattform für Versionsverwaltung und Zusammenarbeit mit Git-Repositories.

## Git und GitHub: der Unterschied

| Aspekt | Git | GitHub |
|---|---|---|
| Typ | Versionskontrollsystem | Plattform für Hosting und Zusammenarbeit |
| Laufort | lokal auf Rechnern/Servern | online im Browser |
| Hauptfunktion | Historie und Branches verwalten | Repositories teilen, reviewen, koordinieren |

## Zentrale Begriffe

### Repository

Ein Repository enthält Dateien, Historie, Branches und Metadaten eines Projekts.

### Commit

Ein Commit ist ein gespeicherter Aenderungsstand mit Nachricht, Autor und Zeitstempel.

### Branch

Ein Branch ist ein separater Entwicklungszweig.

### Pull Request

Ein Pull Request ist ein Vorschlag, Änderungen aus einem Branch in einen Zielbranch zu uebernehmen.

### Issue

Ein Issue dient zur Erfassung von Aufgaben, Fehlern oder Ideen.

## Typischer Workflow

1. Änderung in einem Branch erstellen
2. Commits anlegen
3. Branch auf Remote pushen
4. Pull Request erstellen
5. Review und Merge

## Sichtbarkeit von Repositories

| Typ | Bedeutung |
|---|---|
| Public | Jeder kann Inhalte lesen |
| Private | Zugriff nur für berechtigte Personen |

## README als Einstiegspunkt

Die Datei README.md erklärt Zweck, Nutzung und Struktur eines Repositories. Sie ist häufig die erste Datei, die Besuchende lesen.
